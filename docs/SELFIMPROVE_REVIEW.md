# Self-improvement loop: adversarial review (reward hacking / integrity)

Scope: `docs/SELFIMPROVE.md`, `src/selfimprove/*`, `harness/selfimprove/*`, `modal/selfimprove_eval.py`. Method: read the code as an
attacker who controls only the proposed edit (diff mode: any line inside `NS-EDITABLE` regions; structured mode: five integers), then
for each real hole write a failing CPU test (`src/selfimprove/tests/test_review.py`, committed first) and apply the smallest fix.
No gate was weakened; every fix tightens. No GPU / Modal / live run was used. Test status: `cd src && python -m pytest -q selfimprove/tests`
passes (199+ tests). Existing `results/selfimprove_*` stores still verify under the new `assert_healthy`.

## Confirmed holes (test failed before, fixed)

| # | Hole | Severity | Fix |
|---|------|----------|-----|
| 1 | Planted `.pyc`: `sandbox.manifest` ignored `__pycache__`, `.git`, `.pytest_cache` and every `*.pyc`, so a candidate-run process (the compiled binary, same uid, cwd = workspace) could drop a `harness/selfimprove/__pycache__/common.*.pyc` with a forged mtime/size header; the next harness command imports it = full takeover of the scorer, undetected by the post-command hash check. | Critical | `Workspace.verify` now hashes pyc/`__pycache__`/everything except `_scratch` and `build`. Any new file is `unexpected_file`. |
| 2 | `build/` tampering: `build/` was unhashed, so during a candidate command the binary could overwrite the baseline binary (other workspace, same uid) or its own sibling, e.g. slow the baseline to inflate speedup. | High | `Workspace.freeze_build()` (called right after the build step, or immediately when there is none): `build/` is then hashed on every `verify()`. |
| 3 | Forged result lines: `RunResult.json` took the LAST nonce line and the evaluator did not check the exit code. A child that reads the nonce from `/proc/<ppid>/environ` (`os.environ.pop` does not scrub the initial env block) and writes to `/proc/<ppid>/fd/1`, then hangs the harness so it dies without emitting, gets its forged `time_ms` accepted. | High | A result is trusted only if rc==0 and not timed out, and exactly ONE nonce-bearing line exists (two lines = ambiguous = rejected). |
| 4 | Static audit evasions (diff mode): per-line regexes missed backslash-spliced identifiers (`cuda\` + `EventElapsedTime`), tokens split across lines (`std::` / `chrono`), multi-line `if (n ==` / `7)` shape specialization, `#include "/proc/self/cwd/results/routing_traces.json"` / `.incbin` (embed held-out data), `#define`/`##` token pasting (rename the timer), `openat`/`syscall`/`std::fstream`, `socket`/`connect` (the audit had no network rule; only Modal's `block_network` stood in the way), `posix_spawn`/`vfork`/`setsid` (escape the process-group kill, survive the post-command verify and edit files between commands). | High (diff mode; structured mode renders only digits) | `audit.py`: rules also run over the spliced/joined added text; new `preprocessor` (C sources), `inline_asm_or_embed`, `network` rules; extended `file_io` and `env_or_process`. | 6 | Baseline correctness run failure was ignored: `correctness_gate(cand, base=None)` silently skips the regress-vs-baseline check (and `rb_.timed_out` was never read). | Medium | `Evaluator` returns `baseline_broken` when the baseline correctness run times out or is unparsable. |
| 7 | Any non-`SandboxViolation` exception inside `Evaluator.evaluate` (e.g. `KeyError` on a malformed baseline case) propagated out of `Loop.step` before `st.log`: the proposal vanished from the chain. | Medium | Caught: verdict `evaluator_error`, logged, never promoted. |
| 8 | Store state not bound to the chain: editing `versions/vN/files/*` or `meta.json` (`authored_by`, `north_attested`: attribution spoof), or pointing `CURRENT` at any version, was undetected by `verify_log` and the Loop trusted `st.files(CURRENT)` as the speedup baseline. Rollback could land on a tampered version. | High | `promote`/`init` log records pin `meta_sha256` (meta pins every file hash). `Store.assert_healthy()` (chain + pinned meta + file hashes + `CURRENT == log`) runs in `Loop.__init__` and every `step`; `rollback` verifies its target; CLI `verify-log` runs it. Legacy records without the pin skip only that pin. |
| 9 | Partial commit / ordering: `promote` did `_commit_version` -> `_set_current` -> `log`. ## Checked, no hole found
- Editing the harness, held-out data, gates or thresholds: diff allowlist + `regions_only` + marker-balance + identical protected-tree hashes for base/cand + thresholds live in the evaluator-side `EvalConfig`. Structured mode only rewrites `constexpr int NAME = <digits>;` on a single in-region line.
- Held-out leakage to the proposer: prompt/history carry dev-split numbers only (`history_line` reads `speed.data.dev`); the held-out quality/speed numbers are logged but never fed back.
- Fresh seed per correctness evaluation (`secrets.randbits(48)`), baseline and candidate share it.
- Interleaved A/B, order alternated, same GPU container. Budget cap counts proposer + evaluator cost, including failed evaluations.
- `needs_review` is never auto-promoted; mock never promoted unless `allow_mock_promotion`.

## Statistics (reviewed, unchanged)
- Speed: percentile bootstrap of ratio of medians, 95% two-sided; the gate uses the lower bound (effectively one-sided 97.5%), threshold `1 + max(0.03, 2*max(MAD_rel))`, indexes `int(a/2*B)` and `int((1-a/2)*B)-1` are correct. Held-out must not be slower beyond noise AND the held-out point speedup must reach `1 + 0.25*(dev-1)`; the latter bounds the otherwise generous `1 - noise_floor` allowance (noise is candidate-influenced).
- Quality: paired bootstrap, lower bound at the 5th percentile (`means[int(0.05*B)]`), margin 1e-5 (kernel) / 0.005 (policy). Correct and one-sided.
- Resampling treats base and cand runs as independent although they are interleaved: this is conservative, not a bug.
- Odd `n_runs` (9) gave 5 base-first and 4 cand-first pairs (residual position bias ~1/9 of any order effect). FIXED, see "Residual-risk closure" below.

## Unconfirmed / residual risks (no failing test written; decide before a long live run)
1. **Timer trust.** `time_ms` is the candidate binary's own CUDA-event median (`kernel_bench.py` parses the binary's JSONL). The harness never measures independently. In structured mode the edit is digits only, so this is not reachable; in diff mode macro tricks are now rejected by the audit, but the deny-list is a heuristic (e.g. adjacent string literals `"/pr" "oc"` still evade the `/proc` text rule). Recommendation: keep live runs in structured mode; for diff mode add an independent wall-clock cross-check or an allow-list audit (only `constexpr int NAME = <int>;`).
2. **Held-out data readable by the candidate process.** Held-out traces live in the workspace (hash-protected, not hidden). Reading is blocked only by the audit; there is no mount/seccomp isolation. Moving quality inputs outside the candidate's filesystem view (separate container for scoring, outputs only) is the real fix.
3. **`/proc/<ppid>/environ` still exposes the nonce** and `/proc/<ppid>/fd/1` is writable by a same-uid child. Fix 3 limits damage (single line, rc==0) but a daemonizing child (`setsid` escapes `killpg`) could still race a write between the harness's emit and exit. Audit now rejects the obvious primitives; no `RLIMIT_NPROC` is set (`run()` takes `nproc` but the Evaluator never passes it) because torch threads would count against it.
4. **Network:** blocked only on Modal (`block_network=True`). On a laptop/CI run the sandbox has no network isolation (documented).
5. **Hash chain is unkeyed.** Anyone able to write the store can rewrite and re-chain it. Mitigation is the externally anchored head (app logs); nothing enforces comparing it.
6. **Selection effect over many rounds.** Each promotion uses a 95% bound against the CURRENT (re-baselined) version; with many proposals a lucky noise winner eventually passes and becomes the new baseline, so cumulative speedup can include accumulated noise. A confirmation re-run of the winner before promotion would cost one more evaluation; not added. Report cumulative gains against the original v0000, not against the chain.
7. **Policy track metric is a model prediction** (documented): `time_ms` there is deterministic, MAD = 0, so the speed gate degenerates to point-estimate >= 1.03; and `DEFAULT_SCOPE` still lists `src/opt/policy_tables/*.py`, which would be executed in-process if anyone used it (the shipped `make_config` scopes only `spec_space.json`).
8. **Volume semantics:** `commit()` is called after fsync of each record, but pull reads files non-atomically while the loop runs; staging + consistency check now rejects an inconsistent mix (it fails closed; retry). `max_containers=1` prevents two orchestrators on one store; running local `::main` and `::remote` on the same store name is not guarded.

## Residual-risk closure (second pass; tests in `src/selfimprove/tests/test_residual.py`, CPU only)

| Risk | Status | What changed |
|---|---|---|
| 1 Timer trust | CLOSED for kernel track (live calibration pending) | `kernel_bench.py` now wall-clocks the child itself at harness-fixed rep counts (21 and 3) and emits `ref_ms` (marginal wall per iteration per shape), `n_iters`, `harness_wall_ms`. `gates.timer_crosscheck` (config `EvalConfig.timer = TimerSpec()`) rejects (`gate_fail:timer`) when the binary's self-reported `time_ms` and `ref_ms` disagree by more than `ratio_tol` (4x, either direction), when any field is missing (fail closed), or when the harness's claimed wall exceeds the EVALUATOR's own clock around the whole child. Sound in diff mode: the candidate controls only the binary, not the iteration count or the harness clock. Tests: an under-reporting candidate with unchanged real speed is rejected and passes without the check; the real `kernel_bench.py` driven by a sleeping fake binary. Caveat: `ratio_tol=4` is uncalibrated (ref_ms includes flush/launch and the two-pass variant); the first live run must record the honest ratio and tighten it. A candidate that slows the *baseline*-visible wall and the self-report consistently by <4x is not detected by this check (the interleaved A/B + build/ hashing cover that). Policy track has no timer (deterministic model prediction). |
| 2 Held-out readable in sandbox | CLOSED for kernel quality inputs; held-out SHAPES still in protected harness source | `EvalConfig.heldout_files` (name -> evaluator-side path outside every workspace). `results/routing_traces.json` is no longer in `subdirs`. A workspace containing a file with the same hash or basename as a held-out file is a `sandbox_violation`.
